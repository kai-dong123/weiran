## 一、上游开源项目

| 名称 | 类型 | 版本 / 来源 | 许可证 | 使用方式 | 关键许可义务 | 自研边界 |
|---|---|---|---|---|---|---|
| MiroFish | 开源软件（多智能体社交仿真引擎） | commit `39d849138ef254f6c737ab4c4705e5545dbe31d4`<br>https://github.com/666ghj/MiroFish | AGPL-3.0 | **只复用两样**：① 可用动作列表（`TWITTER_ACTIONS` / `REDDIT_ACTIONS`）② profile 格式定义。**仿真驱动脚本自研**，未复用上游 `run_parallel_simulation.py` | 保留版权与许可声明；衍生作品同样以 AGPL-3.0 发布；向网络用户提供完整对应源码 | 见第三节 |

**为什么驱动脚本不复用上游那份。** 上游 `run_parallel_simulation.py` 共 1699 行，其中真正与 OASIS 交互的不到三分之一，其余是给「Web 端实时下发命令」准备的：IPC 命令目录轮询、`env_status` 心跳、等待命令循环、双平台并行、信号处理。本项目是**批式推演**——跑一轮、拿动作、推进世界状态、再跑下一轮——那套常驻机制是纯粹的负重。更硬的理由是：**世界状态引擎必须逐轮拿到动作**，而上游把动作写进 OASIS 自己的 SQLite 就不再管了。这个逐轮闭环是自研核心，夹在别人的驱动里会很别扭。（上游那套的用途是让人在网页上对正在跑的 agent 做访谈；本项目保留 `ManualAction` 做**事件注入**，效果相同而实现简单得多。）

出处：`backend/weiran/simulate.py:1-19`（模块 docstring 即上述理由）、`:46-55`（动作列表及其上游行号）。

## 二、第三方依赖与服务

| 名称 | 类型 | 版本 | 许可证 / 授权 | 使用方式 | 关键义务或限制 | 合规状态 |
|---|---|---|---|---|---|---|
| camel-oasis | Python 库 | 0.2.5 | **Apache-2.0**（随包 `licenses/LICENSE` 实读确认） | 多智能体社交平台仿真内核 | **版本锁定，不可升级**——上游驱动对 oasis 内部做了 monkey-patch，版本一变就碎 | ✅ 已核实 |
| camel-ai | Python 库 | 0.2.78 | **Apache-2.0**（随包 `licenses/LICENSE` 实读确认） | 模型接入层 | 版本锁定。另注：它对 `mcp` 的上界开放，pip 会解析到 2.x 而 `FastMCP` 已移出 `mcp.server`，因此 `requirements.txt` 必须补 `mcp<2` | ✅ 已核实 |
| DeepSeek API | 模型服务 | 模型 id `deepseek-flash` | 服务条款 | 系统全部 LLM 调用（归类、推演、抽取） | 遵守其服务条款与使用政策 | ✅ 已实测打通 |
| 嵌入模型 | 模型服务 | 未接线 | — | 向量检索 | 向量列与检索通路已就位，**默认关闭**（见下） | 未启用 |

> **版本锁定是刻意的，不是懒。** `requirements.txt` 与 `pyproject.toml` 里对仿真内核写死版本，
> 并在 README 中说明「请勿单独升级」——这不是保守，是因为升级会静默改变仿真行为。

> **嵌入通路的状态要说清楚**：`store.py` 有向量列与 `search_vector()`，但**没有调用嵌入服务的客户端**，
> 因此该通路当前跑不出向量。语料仅 33 个 chunk 的规模下，混合检索不会带来可测量的召回提升，
> 所以只保留词法与向量两条**独立**通路，不做融合——这一点在技术报告中如实写明，而不是假装做了。

> **本清单不含 Flask。** 本项目是 CLI 优先，不提供 Web 服务，因此不声明 Web 框架依赖。
> 项目取向是「每少一个依赖，就少一个『装不上』的失败点」。

> AGPL-3.0 第 13 条：本项目若以网络服务形式对外提供，须向使用者提供完整对应源码。
> 本项目公开发布于代码托管平台，满足该义务。

## 三、自研边界（本项目原创部分）

> 逐项列出并注明对应文件路径。此节是「AI 与开源融合」评分项中「自研边界」的直接依据。
> 行数为实测（`wc -l`），测试条数为 `python -m pytest` 实测。

| 模块 | 文件 | 说明 | 状态 |
|---|---|---|---|
| 世界状态引擎 | `backend/weiran/world_state.py`（603 行） | 六维耦合弛豫模型：逐维半衰期、耦合矩阵、信任/稳定/极化的非对称折扣、拐点与事件检测、反事实干预 | ✅ 已完成（17 条测试） |
| 本地知识存储 | `backend/weiran/store.py`（384 行） | SQLite schema + FTS5 全文检索 + 向量列。**替换上游硬锁的 Zep Cloud**，理由不是「Zep 不好」，而是评委要能一条命令跑起来 | ✅ 已完成（14 条测试） |
| 场景装载 | `backend/weiran/scenario.py`（193 行） | 种子材料 → episodes / chunks / entities。**不调用任何 LLM**，可离线跑、可进 CI、可作为复现起点 | ✅ 已完成 |
| LLM 抽取管线 | 待建 | 实体识别与关系抽取，是 `scenario.py` 之上的增补（确定性装载已先行，LLM 抽取非前提） | 未开始 |
| 行为归类器 | `backend/weiran/stance.py`（223 行） | agent 自由文本 → 六维行为信号。离线重放的确定性关键词匹配在自由文本上失效（实测 12 条生成帖文里 10 条落进默认类、另 2 条归错），故另建在线归类器 + 落盘缓存 | ✅ 已完成（26 条测试） |
| 角色画像 | `backend/weiran/profiles.py`（653 行） | 金标 27 角色 → OASIS profile（`twitter_profiles.csv` / `reddit_profiles.json`）+ 知情映射（`actor_knowledge.json`） | ✅ 已完成 |
| 推演驱动 | `backend/weiran/simulate.py`（736 行） | **自研** OASIS 批式驱动：读动作 → 归类 → 推进世界状态 → 落盘 | ✅ 已完成 |
| 金标校验 | `backend/weiran/validate.py`（387 行） | 用世界状态引擎离线重放场景 + 10 条可机检断言。**不含 LLM、不含随机数** | ✅ 已完成 |

| 可复现性分级自检 | `backend/repro_check.py`（180 行） | 三层复现自检：归类确定 ✅ / 引擎确定 ✅ / 端到端**不可复现** ❌ | ✅ 已完成 |

**合计**：9 个自研模块共 3,573 行 + 4 套离线测试共 1,278 行 = **76 条测试全绿**。
