# 「未然」使用手册

**这份文档与 `README.md` 的分工：** `README.md` 回答「这是什么、为什么这么做」——
问题背景、闭环怎么闭上的、每个设计取舍的理由。**这份手册回答「怎么把它跑起来」**——
环境、命令、产出在哪、每个字段怎么读、以及**哪些数是不能按字面读的**。

两份文档都**只写配置项的名字与含义，绝不写任何一项的值**。

---

## 0. 三十秒版

如果你已经 clone 下来、只想确认「这台机器上能不能跑」：

```bash
cd backend
python -m pytest tests/          # 432 条离线测试，不联网、不需要密钥
python -m weiran.validate        # 离线重放校验（不含 LLM、不含随机数）
python -m weiran.brief           # 决策简报，读已有产出
python -m weiran.viewer --check  # 展示层自检（不需要 flask）
```

**上面四条都不需要 API key。** 它们覆盖了除「真的调 LLM 跑一场推演」之外的全部环节。
要跑那一层，见 §2.3。

## 1. 环境

### 1.1 运行时

- **Python 3.10+**（本项目在 3.11.9 上开发与验证）。
- **SQLite 需带 FTS5 支持。** Python 官方发行版自带的 `sqlite3` 通常已满足；
  若报「未编译 FTS5 支持」，换用 python.org 的官方发行版。这条不是可选项——
  场景库的检索依赖它。

### 1.2 依赖

```bash
pip install -r requirements.txt
```

`requirements.txt` 分三段：

| 段 | 内容 | 说明 |
|---|---|---|
| 核心运行时 | `requests`、`numpy` | 刻意不引入 openai SDK / python-dotenv——需求各只有十几行，少一个依赖就少一个装不上的失败点 |
| 仿真内核 | `camel-oasis==0.2.5`、`camel-ai==0.2.78`、`mcp<2` | **版本刻意锁死，勿单独升级**。上游驱动对 oasis 内部做了 monkey-patch，版本一变就碎 |
| 可选：展示层 | `flask>=3.0` | **只有起展示层服务需要它**。不装也能跑全部推演、简报与自检 |

> `mcp<2` 那一行不是保险，是必需品：`camel-ai` 自己声明的是上界开放的 `mcp>=1.3.0`，
> 而 mcp 2.x 把 `FastMCP` 搬走了，于是 `camel-ai` 一导入就炸。这个错只在
> 「clone 下来装一遍」时出现，开发机上装了旧版就看不到。

### 1.3 配置

```bash
cp .env.example .env
```

`.env` 已在 `.gitignore` 中，**不会入库**。提交前自检：`git status` 里不应出现 `.env`。
**下面只列键名与含义，不列任何一项的值。**

| 键 | 必填 | 含义 |
|---|---|---|
| `LLM_API_KEY` | 跑推演时必填 | 服务商密钥 |
| `LLM_BASE_URL` | 跑推演时必填 | OpenAI 兼容端点的**根**地址。注意结尾的 `/v1` 通常在根地址里，客户端自己接 `/chat/completions` |
| `LLM_MODEL_NAME` | 跑推演时必填 | 对话模型 id |
| `LLM_SEND_THINKING_PARAM` | 可选 | 是否发送 `thinking` 参数关掉推理。实测本项目所用端点默认开推理，思维链占输出 token 的九成以上。**换端点时若报 400，把它设为 0** |
| `EMBEDDING_API_KEY` / `EMBEDDING_BASE_URL` / `EMBEDDING_MODEL` | 当前不必填 | 嵌入模型。**当前未启用**：向量列与检索函数已就位，但没有调用嵌入服务的客户端；33 个 chunk 的规模下混合检索没有可测量的收益，故只保留通路不接线。留空时 `EMBEDDING_*` 回落到 `LLM_*` |
| `OASIS_DEFAULT_MAX_ROUNDS` | 可选 | 推演轮数旋钮。由 `simulate.py` 的 `--rounds` 默认值消费，命令行显式传参优先 |
| `OASIS_MAX_AGENTS` | 可选 | agent 数旋钮。同上，由 `--agents` 消费 |
| `FLASK_HOST` | 可选 | 展示层监听地址。**只接受回环**（`127.0.0.1` / `localhost` / `::1`），填别的值会直接报错停下 |
| `FLASK_PORT` | 可选 | 展示层监听端口 |

配置来源的优先级：**真实环境变量 > 仓库根的 `.env` > 默认值**。所以临时调试可以直接
`LLM_MODEL_NAME=<某个模型> python -m weiran.simulate`，文件里的值不会被覆盖。

**缺失的配置会在第一时间、以能读懂的方式报错**，并且一次性列出**全部**缺失项——
不玩「修一个报一个」的来回。这是刻意的：这类项目最常见的失败不是算法错，
而是跑到一半发现某个 key 是空的。

#### 关于「死的旋钮」

`OASIS_*` 与 `FLASK_*` 这几组键**都曾经是死的**——写在 `.env.example` 里，
但没有任何消费方：设了不生效、不报错、不降级。现在它们各自有消费方
（`simulate.py` 的默认轮数/规模、`viewer.py` 的监听地址），
`tests/test_config.py` 里有回归测试盯着这条接线：**谁把消费方删了，测试会红**，
而不是安静地退回「设了不生效」。

> 这一条值得单独说明，因为它是本项目的**主要猎杀对象**：一个写下来、看起来生效了、
> 实际没生效的配置项。同样的模式在本项目里出现过多次（还有一次是「开关声称回注开着，
> 但逐轮注入次数为 0」——于是有了 `no_injection` 这条降级项）。

## 2. 四种跑法

下面四条**按「要不要花钱」排列**。前三条都不花钱。

**注意工作目录：** `weiran` 包位于 `backend/` 下，所以下面所有命令都假定
你已经 `cd backend`。若想从任意目录调用，执行一次 `pip install -e .`。

### 2.1 跑法一 · 离线自检（不联网、不需要密钥）

```bash
cd backend
python -m pytest tests/                      # 432 条，一次跑完（推荐）
```

十六套测试**也都能不装 pytest 直接跑**（各自带兜底 runner）：

```bash
python tests/test_store.py          # 14
python tests/test_world_state.py    # 23
python tests/test_llm.py            # 33
python tests/test_stance.py         # 26
python tests/test_perception.py     # 49
python tests/test_brief.py          # 55
python tests/test_gold_check.py     # 31
python tests/test_selfcheck.py      # 8
python tests/test_simulate.py       # 36
python tests/test_config.py         # 13
python tests/test_repro_check.py    # 13
python tests/test_viewer.py         # 24
python tests/test_stability.py      # 11
python tests/test_handbook.py       # 28
python tests/test_stability_report.py  # 31
python tests/test_run_seeds.py     # 37
```

另外三条**不跑 LLM 的**验证入口：

```bash
python -m weiran.scenario --reset    # 把种子材料装进本地知识库（不调 LLM）
python -m weiran.validate            # 世界状态引擎离线重放校验
python -m weiran.brief               # 决策简报：读已有产出，生成 brief.md + brief.json
```

三条各回答一个不同的问题，**别混着读**：

- `scenario` 问「场景库装进去了没有」。预期输出形如
  `本次写入 episodes=5 chunks=33 entities=27`。
- `validate` 问「引擎重放场景时，六维轨迹与金标差多少、10 条断言成立不成立」。
  **它输出里有一个 MAE 数字，那不是分数。** 见 §3.6。
- `brief` 问「把这一次产出摊成可比较的处置方案，长什么样」。

> **这些离线测试证明不了「推演命令发出去真的能跑通」**——这一条是被实测撞出来的：
> `repro_check.py` 的第 3 层一度传了个**文件名**给 `--out`（而它要的是目录），
> 那条命令必炸，而当时九套测试全绿——因为它们测的是参数字符串，
> 不是那条命令真的跑起来。要验这一层，只能真跑，见 §2.2。

### 2.2 跑法二 · 离线重放校验（不联网、不需要密钥）

```bash
cd backend
python repro_check.py
```

它把「可复现性」**分层**量出来，而不是笼统地说一句「我们可复现」：

| 层 | 问题 | 结论 |
|---|---|---|
| 第 1 层 | 同样的文本 → 同样的归类标签？ | ✅ 确定（缓存 + 测试锁住） |
| 第 2 层 | 同样的行为序列 → 同样的六维曲线？ | ✅ 确定（测试锁住） |
| 第 2.5 层 | 同一份产出 → 同一份简报文字？ | ✅ 确定（逐字比对，测试锁住） |
| 第 2.6 层 | 同一份产出 → 同一张金标对照表？ | ✅ 确定（逐字比对，测试锁住） |
| 第 2.7 层 | 那张对照表是不是**算出来的**？ | ✅ 确定（喂反例，见下） |
| 第 3 层 | 同一条命令 → 同一条曲线？ | ❌ **不确定，且原理上做不到** |

**第 2.7 层问的不是「可不可复现」，是另一件事**：上面每一层都是「同一份产出 →
同一份产物」，那么**一个把结论写死的实现能让它们全部通过** —— 把对照表的求值
整个换成一张十行的常量表，第 2.5 / 2.6 层照旧逐字一致、照旧全绿。所以这一层
不比两次运行，它**喂反例**：9 条「真产出 × 单点受控扰动」，每条同时断言
「该动的动了」与「不该动的没动」。命令是 `python -m weiran.selfcheck`。

**第 3 层做不到的原因不在本项目代码里，在上游**：agent 每次说的话都不一样。
缓存只能保证「同一句话给同一个标签」，保证不了「同一场推演说同一句话」。
压 temperature、固定 seed 能收窄抖动，但服务端只「尽力」遵守 seed，给不了逐位保证。
所以正式口径只能是「**多 seed 跑 N 次、报均值与方差**」，而不是「跑一次就准」。

第 3 层会**真的把推演 CLI 拉起来**（默认 `--agents 5 --rounds 3`，压缩模式，
约几分钟、几分钱）。它是唯一一条真的走通推演命令的检查，验收改动时请跑它。
想更快可以 `python repro_check.py --agents 1 --rounds 2`（约 10 秒），
或用 `--skip-e2e` 跳过第 3 层只跑确定的那几层。
**这是本手册里唯一会花钱的命令**（且金额极小）。

### 2.3 跑法三 · 带 LLM 的推演（**要花钱**）

```bash
cd backend
python -m weiran.simulate --rounds 15 --agents 27
```

**先把成本量级说清楚**，再谈参数。实测一场 27 agent × 15 轮：

| 量 | 实测值 |
|---|---|
| 墙钟 | 657 秒（约 11 分钟） |
| 调用 | 400 次（失败 0） |
| token | 入 4377107 / 出 44478 |
| 动作 | 774 条 |

调用次数随 agent 数与轮数**成乘积增长**，而每轮 prompt 还因上下文累积继续变长，
所以总成本比「轮数 × agent 数」增长得更快。跑之前心里有个数。

主要参数：

| 参数 | 含义 |
|---|---|
| `--rounds` / `--agents` | 规模。默认取 `.env` 的 `OASIS_*` |
| `--platform` | `twitter` 或 `reddit` |
| `--out` | 输出**目录**（不是文件名）。缺省写在 `data/simulation/` |
| `--scenario` | 场景目录，默认 `benchmark/scenarios/employment_trust_crisis` |
| `--seed-text` | 附加的种子文本 |
| `--thinking` | 打开推理。默认关闭——思维链占输出 token 的九成以上 |
| `--max-tokens` | 单次输出上限 |
| `--temperature` / `--seed` | 抖动控制。**只收窄，不给逐位保证**（见 §4.8） |
| `--chunking-guard` | 切片护栏。**默认关闭**，见 §4.5 |
| `--keyword-stance` | 用确定性关键词归类，不走 LLM 归类器 |
| `--no-stance-cache` | 不用归类缓存 |
| `--no-world-state` / `--no-phases` / `--no-knowledge` / `--no-feedback` | 消融开关：关掉六维状态引擎 / 阶段事件注入 / 知识注入 / 状态回注。**关掉任何一个，产出里都会多出一条对应的降级项** |
| `--events-from` | 阶段事件从哪来：`phases`（默认，5 条阶段 trigger）或 `event_order`（金标的 17 条事件日程） |
| `--inspect-db` | 看数据库，不跑推演 |

跑完先看产出文件里的 `meta` 与 `cost`，再看简报——不要直接看曲线。

### 2.4 跑法四 · 起展示层（可选依赖 flask）

```bash
cd backend
python -m weiran.viewer --check     # 先自检：把每页渲一遍，不需要 flask
python -m weiran.viewer             # 起服务，地址取 .env（默认 127.0.0.1:8000）
```

展示层把**已经躺在盘上的产物**渲染成五个页面：概览 / 六维曲线 / 逐轮 / 决策窗口 /
金标对照。**它不触发任何 LLM 调用**——「打开页面看一眼」不应该产生一场推演的代价。

设计边界（每条都有理由，写在 `viewer.py` 的模块注释里）：

- **只读。** 只注册 GET 路由；对任意路径发 POST 一律 405，并回一句
  「本展示层是只读的」。
- **只绑回环。** `FLASK_HOST` 填非回环值会直接报错停下，不静默忽略——
  这一层没有任何鉴权，绑到外部地址就是把「本地查看工具」变成对局域网开放的服务。
- **不引 CDN、页面里没有一行 JavaScript。** 图表是**服务端生成的内联 SVG**。
  离线可跑是本项目的取向；一个要联网加载图表库的页面在评委的机器上可能是白屏。
- **「未记录」绝不显示成 0。** 老产出里没有的字段显示「未记录」——一个编出来的 0
  与「真的发生过、量是 0」在页面上长得一样，而这两件事完全不同。
- **每页底部挂着数据文件的路径与 sha256**，看到的每个数都能追回产生它的那次运行。

参数：`--host` / `--port`（默认取 `.env`）、`--brief` / `--rounds` / `--gold`
（换数据源）、`--check`（不起服务，只自检；**缺产物算失败**，因为那是「没测到」，
不是「跳过」）。

**页面上有一个灰置的「触发推演」按钮**——它是预留的接口，没有接任何启动逻辑，
按钮旁边就写着代价与前置条件。接口留在那里是为了让「下一步接什么」看得见，
而不是假装已经有了。

**不装 flask 也能用：** 直接看 `data/simulation/` 下的 `brief.md` 与 `gold_check.md`，
页面与那两份文字读的是同一批数。

## 3. 产出在哪、字段怎么读

产物都在 `data/simulation/`：

| 文件 | 是什么 |
|---|---|
| `twitter_rounds.json` | 推演产出：逐轮状态、动作、行为信号、逐轮调用与用量。**下游的一切都从它算起** |
| `brief.md` / `brief.json` | 决策简报（markdown 给人看、JSON 给程序读）。同输入同输出，可进 CI |
| `gold_check.md` / `gold_check.json` | 金标对照表：金标自己写的 10 条断言逐条核对。**独立产物，不并进简报**，见 §3.6 |
| `*.db` | 本地知识库（场景装载的产物） |

### 3.1 `provenance` —— 先看这个

每个产物开头都有 `provenance`，含数据文件的路径、**sha256**、场景文件与 sha256，
以及**生成它的那条命令**。看的任何数字都能顺着这一块追回产生它的那次运行。
这不是装饰：「这份数是从哪来的」是后面所有解读的前提。

### 3.2 `meta` —— 这一场是怎么跑的

`rounds` / `agents` / `platform` / `seed_text` / `days_per_round` / `phases_on` /
`knowledge_on` / `feedback_on` / `world_state` / `total_seconds` / `total_actions` /
`context_limit` / `truncations` / `truncation_unparsed` / `truncation_worst_dropped`。

**`days_per_round` 是关键的一个**：它不为 1.0 时整条曲线是**压缩模式**，
与「轮 = 天」不可比（理由见 §3.5 的 `compressed`）。

### 3.3 `coverage` —— 决策窗口有没有落到轮上

`by_phase` 给出每个阶段对应的轮号，`n_uncovered` / `n_shared` 给出没有对应轮次
或与其他窗口共用一轮的窗口数。这两个数不为 0 时，简报与金标对照里都会多出降级项。

### 3.4 `evidence` —— 上面那些数字各自的分母

**这一块回答的是「每个读数背后有几条证据」。** 它有两个别的字段名：
`rows`（逐轮的行数、动作数、发声数、参与者数）与 `presence`（在场与发声的分离）；
以及两条**无自由参数**的判据与一条「最薄」统计：

- `railed_rounds` / `railed_dims`：**有维度恰好贴到上下界的轮**与维度名。
  贴界是 `_clamp(·, 0, 1)` 的边界产物，**不是读数**——那些轮次的曲线形状由夹逼决定，
  不由行为决定。
- `no_evidence_rounds`：**零条行为**的轮，却仍有决策窗口落在上面。该轮激励项恒为 0，
  状态是纯弛豫外推。
- `leanest` / `min_n_behaviors`：证据最薄的那一轮及其分母。**窗口数字的可归因性上限
  就是这个分母。**

判据为什么「无自由参数」值得说一句：贴界的判据是 `round(v, 4) in (0.0, 1.0)`——
要么是零、要么是引擎自己的夹逼边界，**都不是本文新定的阈值**。
一条靠自定阈值报警的监测，读者无法判断报警是现象还是阈值选得好。

### 3.5 `degradations` —— **非空就要当回事**

代码里一共定义 **14 种 kind**，当前入库产出触发了 2 种（`truncated`、`railed`）。
`railed_rounds` 非空 ⇒ `railed` 必然出现。逐条：

| kind | 什么时候出现 | 要读成什么 |
|---|---|---|
| `truncated` | 全程发生过记忆截断 | 被截断轮次的 agent 在丢失历史的状态下说话，数字要打折 |
| `truncation_unparsed` | 截断警告解析失败 | **本项监测已不可信，先修它再看结论** |
| `no_context_record` | 产出里没有上下文压力记录（生成于监测接上之前） | **不要读成「没有截断」**，是「没记录」 |
| `no_evidence_round` | 有零条行为的轮，且窗口落在上面 | 该轮状态是弛豫外推，不是测出来的 |
| `railed` | 有维度恰好贴到上下界 | 这些轮次的曲线形状由夹逼决定 |
| `compressed` | `days_per_round ≠ 1` | **与「轮 = 天」不可比**，见下 |
| `not_comparable` | 明确声明不可与 `--rounds 15` 并列 | 别横向比 |
| `small_scale` | agent 数 < 5 | 是小规模敏感性测试，**不能当金标规模（27 角色）的结论** |
| `uncovered` | 有窗口没有对应轮次 | 该窗口没有可归因的读数 |
| `shared_round` | 多个窗口共处同一轮 | 干预相同、分叉点相同，数值必然重复，**不可单独归因** |
| `no_world_state` | 本次未推进六维状态 | 没有曲线可读 |
| `no_phases` | 本次未注入阶段事件 | 所有决策窗口都不会有对应轮次 |
| `replay_mismatch` | 重放与产出记录的最大偏差超 1e-4 | **这份产出很可能不是本引擎按当前参数产生的** |
| `no_injection` | 开关声称回注开着，但逐轮注入次数为 0 | **问题在接线，不在模型** |

`compressed` 为什么不能含糊过去：每轮代表多于一天时，弛豫项 `exp(-k·dt)` 可以复合，
但**激励项按步累加**——同样 7 天拆成 7 步会激励 7 次、合成 1 步只激励 1 次。
两条曲线**不是同一条曲线的粗细版本，是两条不同的曲线**。

### 3.6 `markers` —— 正文里那 7 个方括号标记

简报正文里会出现 7 个固定标记，每个都对应一段必须写出来的声明。它们不是排版，
是**机检的抓手**：`check_brief` 会断言该出现的标记出现、不该出现的不出现，
缺了就让简报生成失败。

| 标记 | 含义 |
|---|---|
| `[不可端到端复现]` | 有 LLM 调用时必须出现（见 §2.2 第 3 层） |
| `[压缩模式·与轮=天不可比]` | `compressed` 为真时必须出现 |
| `[模型内对照·非预测]` | 反事实分支不是预测 |
| `[干预口径为本文自设假设]` | 「还能怎么做」是简报自设的假设，不是金标的事实 |
| `[降级项]` | `degradations` 非空时必须出现 |
| `[上下文压力·已监测]` | **无条件出现**——「没截断」是一条必须主动说出来的结论，不是可以省略的缺省 |
| `[证据量·逐轮]` | **无条件出现**——每一轮的六维状态都是「几条行为算出来的」，这个分母不能省略 |

### 3.7 `cost.paths` —— **两条调用路径分账**

本项目有两条调用 LLM 的路径：camel 驱动 agent 那条，以及 `stance.py` 归类器、
`profiles.py` 画像生成**直调**的那条。两者记在同一个 `cost` 块的不同键下：

- `paths.camel`：calls / token / 以及**前缀缓存命中**（`cache_hit_tokens` /
  `cache_miss_tokens` / `cache_hit_pct`）。`cache_recorded=false` 表示这次运行
  **没记录**缓存——**不是 0**。
- `paths.direct`：归类器那一路的账。若产出生成于记账补全之前，这里是
  `{"recorded": false}`——同样是「没记录」，不是 0。

**「没记录」与「量是 0」在 JSON 里必须长得不一样**，这是本项目反复用的同一条纪律
（简报的 `failures_recorded`、LLM 客户端的 `cache_recorded`、展示层的「未记录」
是同一条纪律的四次复制）。

### 3.8 `gold_check.json` 的三态怎么读

金标对照表把金标自己写的 **10 条断言**拿到**一次真产出**上逐条核对，每条给三个
结论之一：

| 结论 | 读成什么 |
|---|---|
| **通过** | 这次运行里，金标声称的那件事发生了 |
| **否决** | 这次运行里没有发生 |
| **不可判定** | **缺一样东西才能判**，表里写明缺什么（`undecidable_because` / `to_make_decidable`） |

**「不可判定」绝不折成「通过」或「失败」**——三者是三件事。表头写死了这一点，
`summary.judged` 只统计「判得出来」的行，`trusted` 与「不可判定」不共用分母。

还有一层更细的：**判得出来 ≠ 可采信。** 一条断言即使结果为「通过」，
只要它读的那个操作数碰到了贴界轮，就会被降级为**不采信**（`trusted=false`、
`no_trust_because` 里写明原因）；反过来，**一条「否决」如果读了贴界轮，同样不作数**——
**贴界的破坏是双向的**，不能只挑对自己有利的那一边。

入库产出上的读数：**通过 3 · 否决 5 · 不可判定 2；判得出来的 8 条里只有 4 条可采信**。
其中 **AS-2 / AS-3 / AS-4 / AS-8 四条否决指向同一条相位缺陷**——
表里写死了这一句，别读成四个独立问题。

**这张表不是分数。** 它没有分母、没有基准，既不能加总成一个「得分」，
也不能与另一次运行的读数比出「提高了多少」。理由不在这份代码里，在金标自己的话里
（`reference_data.json → gold_status.what_is_NOT_solid`）：`reference_shape` 是
**作者手写的强度预期**，不是观测值，也不是评分基准——任何以它为分母算出的
「准确率」都是自说自话。表里开头那句「这不是分数」是**引用金标自己的话**，
金标里没有这句话时，这张表**拒绝生成**——代金标说这句话，就是替它背书。

## 4. 已知降级项：坦白清单

**这一节列的每一条都是当前版本已声明、未修复的性质。** 它们中的一部分已经写进产物
（会以降级项或标记的形式自动出现），另一部分只在文档里——列在这里是为了让读的人
不必先去读 `进度.md` 的两千多行。

### 4.1 相位缺陷 —— 四条否决的共同根因

**现象：** 引擎读的是行为的**构成占比**，不是**体量**。于是当校园已经安静下来、
`suppression` 在行为里的占比升高时，引擎报出全程最大的驱动——**驱动峰落在
校园已经安静之后**。实测输出峰在 R10 附近，而场景转折点在 R5。

**已经试过、都移不动输出峰的三个引擎杠杆：** 耦合饱和、体量常数 `VOLUME_REF`、
事件去稀释。金标对照表里的 AS-2 / AS-3 / AS-4 / AS-8 四条否决全部指向这一条。

**成立范围（重要）：这条是 27 agent 的性质。** 12 agent 时体量项 `tanh(n/V)`
的变动从 24% 涨到 75%，**它自己就把后段压平了**——十支 12 agent 臂里有 7 支的
驱动峰因此**假落在 P3**。

> **纪律：不能拿 ≤12 agent 的臂去判相位问题。** 规模一小，缺陷被这一项掩盖，
> 看起来「峰正好在 P3」——那不是模型对了，是这一项在替它答。

### 4.2 后段 agent 可见记忆 ≤ 1.31%

27 agent 那场里，最坏的一轮 agent 能看到的记忆**不超过自己的 1.31%**，
且 camel 是**按打分丢低分**的——留下的不保证是最近的那一段。

这个数不是估计，是**上界**：由 `before = after + dropped` 且 `after ≤ limit` 得
`after / before ≤ limit / (limit + dropped)`，只用产出里已有的两个字段就能算出来。
换算成比例是刻意的——「丢了 123 万 token」读者判断不出量级，
「还能看到 1.31%」可以。

### 4.3 `truncations = 767`

27 agent × 15 轮那场全程 767 次记忆截断，单次最多丢弃 1234443 token
（上下文窗口上限 16384）。被截断轮次的 agent 在丢失历史的状态下说话，
**这些轮次的数字要打折**。产物里会自动出现 `truncated` 降级项。

### 4.4 「agent 集体安静」已被证伪

一个曾经的前提是「agent 在 P3 之后集体安静」。**实测证伪：**

- **在场人数全程恒定**（`participants_min` / `participants_max` 相差 1，
  首末分别为 26 / 27）；
- 衰减的是**产出内容的人**：发声者 21 → 8，`do_nothing` 一类动作 5 → 16。

所以正确的说法是「**产出信号的 agent 变少了，而不是 agent 离场了**」。
这条区分进了 `evidence.presence` 块，判据是严格比较、没有阈值。

另有一条**旧结论已作废**：「3 agent 全程零截断」——6 次同规模实测 0 次复现。
它当时那次确实没截断，但那是「一次运行的运气被写成了规模结论」。

### 4.5 `--chunking-guard` 默认关闭（**待决**）

已定位的真机制：camel 在预算耗尽时把每条消息切成 1 token 的小块，
而截断只留得下最后那一小截，形成「越满越碎、越碎越满」的反馈环
——**不是 agent 记得多**。修法 `--chunking-guard` 已落地并双向自检。

实测收益（护栏 3 支 vs 对照 2 支，12×15）：最坏一次丢弃 1/12.7~1/20.5、
截断 1/4.8~1/6.3，**两条区间不重叠**；「agent 实际读到什么」的探针显示
护栏关着时 16k 上下文里 99.4% 是切片碎片，打开后碎片 0。
行为侧：护栏确实拦下（早先记录的「动作少 18%」在补齐数据后消失，
证明那 18% 是被端点 400 丢掉的回合，已修）。

**但它默认关闭，且「要不要默认开」列为待决。** 证据一边倒，可是默认开意味着
**既有产出（入库简报样例、金标曲线、「可见记忆 ≤1.31%」那类声明）全部重跑**。
这个决定不一个人拍。

### 4.6 另外两项待决

- **每轮注入体量该不该减？** 接受现状、把「可见记忆 ≤1.31%」写成已声明性质；
  或者减体量做保真性修复，但要重跑金标规模。
- **`VOLUME_REF` 该不该改成随 agent 数走？** 有独立理由（体量项须在观测范围内
  真正变化，否则引擎退化成只读构成），代价是**离线重放路径被压到近零驱动**
  （`tanh(n/V)` 在 n=5 时 V=8 → 0.555、V=27 → 0.183）。

**这两条如实写成待决，不写成结论。**

### 4.7 明确没有做的事

- **反事实不是预测。** 分支假设「后续行为不变」，而现实中一旦真的公开，
  agent 的反应本身就会变——那正是模型答不了的部分。A／B 两版**不是区间**，
  是两个模型假设下的两个点，**不构成上下界保证**。
- **端到端不可复现**（§2.2 第 3 层）。任何一次运行的曲线都只是**一个样本**，
  正式口径应当是「多 seed 跑 N 次、报均值与方差」。**工具已经就位**
  （`run_seeds.py` 起批次、`stability_report.py` 汇总），
  **但一批还没跑** —— 原因写在 §4.8 末段：两项待决常数任一改动都会让
  已跑出来的臂作废。
- **知识图谱检索尚未接线。** 向量列与检索函数已就位，但没有调用嵌入服务的客户端。
- **没有 per-agent 的认知动态层。**
- **相位修改本身没做**——只做到了定案（读占比、峰在安静之后、三个杠杆都移不动）。

### 4.8 稳定性与可复现性：边界在哪、工具在哪、批次为什么还没跑

**先分清「确定」与「不确定」。** 本项目自己写的那几层是**确定的**：六维状态引擎
`world_state.py` 全模块零抽签（`WorldStateEngine.step` 是 `(state, behaviors, dt,
phase_id)` 的纯函数）、阶段划分与事件注入来自金标、归类只在缓存未命中时才发 LLM、
`brief.py` / `gold_check.py` 声明「同输入同输出」。会变的全在**上游**。

下表是**会变的那五处**，与 `backend/weiran/stability.py` 的 `VARIANCE_SOURCES`
**同源**（有一条测试逐行比对，两边各写各的会红）：

| 来源（代码里的 key） | 哪一层会变 | 能不能收窄 |
|---|---|---|
| `llm_agent_sampling` | camel 侧 agent 的 LLM 采样 | 部分：`--seed` / `--temperature` 已接通，但 `seed` 只被服务端「尽力」遵守 |
| `llm_direct_sampling` | 直调路径（归类器）的 LLM 采样 | 能，默认关 |
| `oasis_feed_sampling` | OASIS 的 `refresh`：**决定 agent 每轮看到什么 feed** | 能，且是决定性的（上游全库不自己播种） |
| `asyncio_interleaving` | `asyncio.gather` 的并发交错顺序 | **不能**：那不是随机数，播种覆盖不到 |
| `camel_retry_jitter` | camel 限流重试的退避抖动 | 顺带被全局播种覆盖；只影响墙钟 |

**第 3 行是这份清单里此前被漏掉的那一格。** `refresh` 不是 LLM 选的，是上游在
**构造每个 agent 每轮观察**时自动发的（`social_agent/agent_environment.py:59`），
`platform.py:277` 在那里用 `random.sample` 抽进 feed 的帖子。它用的就是标准库那个
**全局** `random` 模块，而 `oasis` 与 `camel` **全库从不调用 `random.seed()`** ——
所以在自己的进程里播一次种就能覆盖它。`--seed` 现在同一个数做两件事：作为请求
字段送给两个 LLM 端点，以及给本进程的全局 RNG 播种。

**它买到的是「钉住」，不是「可复现」。** 第 4 行播种覆盖不到：`asyncio` 的并发
交错顺序决定 DB 写入次序 → `post_id` 分配 → 后一个 agent 点赞/引用的是哪条帖，
而那不是随机数。**跨次比较请按「多 seed 多次、看离散」读，不要把单次产出当
可复现结论。** 这句话每个产出的 `meta.sampling_note` 里都带着。

**怎么起一批**（顺序跑、不并行 —— 墙钟是被记录的量）：

```bash
cd backend
python run_seeds.py --seeds 11,22,33 --agents 27 --rounds 15 --temperature 0.7 --out data/runs/seeds
```

**不给 `--yes` 时它一个请求都不发、一个目录都不建**，只打印计划与估算（估算从
入库那份产出里读实测读数，按「agent×轮数」线性外推，**标明是外推不是测量**，
且**不报金额** —— 仓库里没有写死单价）。确认无误再加 `--yes`。

跑之前先花十几秒验前提：

```bash
python run_seeds.py --seeds 11 --agents 27 --preflight
```

`--preflight` 用同一个 seed、`--agents 1 --rounds 2` 跑两次，比对 `state` 曲线与
`behaviors` 序列。**它不需要 `--yes`，但它不是免费的** —— 那两次是**真推演**，
真发请求（只是规模只有 1 agent × 2 轮，实测约十秒，所以从**计划**那一侧看它
便宜到几乎免费；从**调用**那一侧看它仍然在花钱，别把它当成一次 dry-run）。**若同一 seed 两次都不一致，先别跑那批 27 agent 的臂** ——
该如实报告「seed 达不到可复现」，而不是花钱买一批更贵的不可复现产出。但它
**推不到 27 agent**：1 个 agent 几乎不触发并发交错，而那一层恰恰播种覆盖不到。

驱动会拒的几件事（每条都有测试）：目标臂目录已有且口径不符（要 `--force` 才覆盖）、
底本缺**必需件**（`twitter_profiles.csv` / `actor_knowledge.json`；`stance_cache.json`
是可选加速件，缺了照跑、只是慢）或与上一批不同源、臂之间口径不一致、`--seeds` 里有重复、少于 27 agent
不开口子，以及 `--jobs` / `--parallel` **根本不存在**。它也不用 `--out` 默认值 ——
产出目录是必传的。

**怎么读汇总**：

```bash
python stability_report.py --root data/runs/seeds
```

逐轮逐维给出跨臂均值与范围、驱动峰是否一致、金标三态逐臂重算后是「稳」还是
「翻转」，以及「跨臂离散 ÷ 臂内相邻轮步长」的比值（**比值小**才谈得上有信号；
**本表不设阈值** —— 没有客观分界）。它**纯离线、无网络、无 LLM**。

**它报的不是分数。** 跨 seed 一致**不等于**结论对：一个系统性偏差会在每一个
seed 下一模一样地重现，一致性只能界定**抽样误差**那一部分。汇总器会拒绝四类
批次：拿一支臂拷成 N 份（离散恒等于 0）、口径不一致的混合批次、同一 seed 记两次、
以及接不上重放的臂（一支对不上 = 该臂产物可能被手改过，排除并点名；全部对不上
= 引擎换过，**不给读数**）。

**那为什么一批还没跑？** 两项待决常数（§4.5 的 `--chunking-guard`、§4.6 的每轮
注入体量与 `VOLUME_REF`）**任一改动都会让已经跑出来的臂作废**。所以次序是：先把
零成本的一半与决策材料做完，拍板之后再起批次。若决定「先在现有基线上跑一批看
看」，上面两个工具直接可用。
