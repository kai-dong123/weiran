面对校园突发事件，管理者往往在两难中做决定：公开信息会引发舆情，不公开则损耗信任。
**「未然」把这场两难提前演练一遍**——用多智能体仿真重放事件的舆论演化，逐轮追踪
关注、恐慌、信任、极化、风险、稳定六个维度的状态，识别风险拐点，并在你真正开口之前
给出可比较的处置方案。第三件事由 [`brief.py`](backend/weiran/brief.py) 产出——
它把金标的 5 个决策窗口逐行摊开，在每个窗口上都问一次「当时换个做法会怎样」，
并把「这只是模型内的对照、不是预测」写进正文、用机器检查强制它在场。

**闭环是怎么闭上的。** 每一轮：读 agent 的动作 → 归类成行为信号 → 推进六维状态 →
**把状态重新注回下一轮每个 agent 的输入**。回注的不是数值而是定性档位与方向
（「信任偏高、下滑中」），原因是数值会被 agent 原样复述进帖文，曲线就成了回声。
回注的还有**差异化感知**：同一时刻，家长只知道落实率，而当事人知道核实率只有
三成且对外不披露——事实按角色注入，而不是在提示词里写死一段背景故事。
**事实还按阶段裁**：金标里描述「事件发生之后才存在」的信息（删帖通知、自媒体
转载）带 `phase` 标签，到那个阶段才注入。第一版没有这一层，于是 8 个角色在
第 0 轮就拿到了 P3/P4 才发生的事——注入照常发生、各人不重样、测试全过，
只是把未来告诉了 agent。现在有测试专门断言「某条事实在第 0 轮**不在场**」。
五个阶段事件（P1–P5）同样从金标按轮号注入，且**以帖子的形式进入时间线**，
六维的变化经由 agent 的反应发生，而不是直接给维度加激励。

## 快速开始

### 1. 环境

Python **3.10+**（本项目在 3.11.9 上开发验证）。
需要 SQLite 带 **FTS5** 支持——Python 官方发行版自带的 `sqlite3` 通常已满足；
若报「未编译 FTS5 支持」，换用官方 python.org 的发行版即可。

### 2. 安装依赖

```bash
pip install -r requirements.txt
```

> `requirements.txt` 里的仿真内核（`camel-oasis==0.2.5` / `camel-ai==0.2.78`）是
> **刻意锁死的**——上游驱动脚本对 oasis 内部做了 monkey-patch，版本一变就碎。
> 请勿单独升级。

### 3. 配置

```bash
cp .env.example .env
```

然后编辑 `.env`，至少填入：

| 变量 | 说明 |
|---|---|
| `LLM_API_KEY` | 服务商密钥 |
| `LLM_BASE_URL` | OpenAI 兼容端点根地址，形如 `https://api.deepseek.com/v1` |
| `LLM_MODEL_NAME` | 对话模型 id |

`.env` 已在 `.gitignore` 中，**不会入库**。提交前自检：`git status` 里不应出现 `.env`。

### 5. 跑一次推演（**需要 API key**）

```bash
cd backend
python -m weiran.simulate --agents 5 --rounds 15    # 轮 = 天，推荐口径
python -m weiran.simulate --agents 3 --rounds 3     # 省钱冒烟（会压缩，见下）
```

> **做消融对照时请把 `--out` 指到一个别处。** `--out` 的默认值是
> `data/simulation`，而**推演往那个目录里的 `twitter_rounds.json` 写产出**——
> 所以跑任何一次推演都会覆盖仓库里那份入库产出，包括 `--no-feedback`
> 这类只为看一眼的消融。这不是假想的风险：自检脚本正是栽在这一条上，
> 而且修它的时候又栽了第二次（见「设计取向」最后一节）。
>
> **`--out` 的粒度是「运行目录」，不是输出文件名。** 这一点会绊人：
> 推演从那个目录**读**画像（`twitter_profiles.csv`）与知情映射
> （`actor_knowledge.json`），再往它里面**写**产出。所以
> `--out /tmp/ablation.json` 这种写法会在读画像那一步 `FileNotFoundError`,
> 正确做法是先造一个喂饱了的目录：
>
> ```bash
> mkdir -p /tmp/abl && cp data/simulation/{twitter_profiles.csv,actor_knowledge.json} /tmp/abl/
> # 第三份 `stance_cache.json` 是**可选加速**、不入库：本地有就顺手带上
> # （`cp data/simulation/stance_cache.json /tmp/abl/ 2>/dev/null || true`），
> # 没有就直接跑 —— 推演会自己归类，只是多花 LLM 调用。
> python -m weiran.simulate --agents 5 --rounds 15 --no-feedback --out /tmp/abl
> python -m weiran.brief --rounds-file /tmp/abl/twitter_rounds.json
> ```
>
> `repro_check._seed_run_dir()` 做的就是上面那个 `cp`（并可被离线测试），
> 自检脚本的第 3 层走的就是它。

闭环的三个开关**默认全开**，都可以单独关掉做消融对照：

| 开关 | 关掉之后 |
|---|---|
| `--no-phases` | 不注入 P1–P5 阶段事件，时间线只剩 `--seed-text` |
| `--no-feedback` | 不回注六维态势 |
| `--no-knowledge` | 不回注该角色的知情范围 |

**事件注入源有两条，`--events-from` 选**（默认 `phases`，暂不改）：

| 取值 | 注入什么 | 有事件的轮 |
|---|---|---|
| `phases`（默认） | 5 条阶段概括 `trigger`（「报告挂网，落实率 78.6% 曝光」…） | 5/15（轮 0/2/5/8/14） |
| `event_order` | 金标 `event_order` 那 17 条事件明细（「论坛出现首个质疑帖」「学工部下发劝删通知」…） | 8/15（+轮 4/6/13） |

> `event_order` 是本项目里**一直没被读过**的金标数据 —— 金标写了 17 条带日期的事件，
> 而注入只用 `phases` 那 5 条，两者差 12 条，且不报错、不提示。
>
> **但它不是一个「更全」的开关**：轮 9–12 在两条口径下**都没事件**（金标 day 9–12
> 本来就没有事件），所以它**填不上**后段那个空档。落盘的 `meta.events_from` 会写明
> 用的是哪条口径 —— 两条口径的曲线不可混引。
>
> **仓库里那份 27 agent 产出早于这个字段**，所以它的 `meta` 里没有 `events_from`
> （读出来是 `None`）。它跑于默认口径，即 `phases`；这里明写，免得日后再去猜。

> **轮数少于 15 会被压缩**（每轮代表多于一天），此时六维曲线**与「轮 = 天」
> 不可比** —— 弛豫项可以复合，但激励项按步累加，同样 6 天拆成 6 步和合成 1 步
> 是两条不同的曲线。落盘的 `meta` 里带 `compressed` 与 `comparable_to_round_day`，
> 启动时也会打印警告，免得日后被当成「轮 = 天」的结果引用。

### 6. 生成决策简报（读已有产出，**不花钱**）

```bash
cd backend
python -m weiran.brief                    # 默认读 data/simulation/twitter_rounds.json
python -m weiran.brief --stdout           # 顺带把全文打到终端
python -m weiran.brief --intervention-scale 1.0
```

产出 `data/simulation/brief.md`（给人看）与 `brief.json`（给别的模块与测试用）。
仓库里那份样例是**一次 `--rounds 15`（轮 = 天）的 27 agent 真实推演**的简报，
**而且没有换掉**：它后段是崩的（见上面那条与 [`进度.md`](进度.md)），
简报自己把它写出来了。换一份好看的进来，就等于把这个项目唯一的金标规模实测
藏起来。

**怎么看它。** 简报把金标的 5 个决策窗口逐行列出：当时当局是怎么做的、该窗口
落到本次运行的哪一轮（轮数不够时会被压缩、两个阶段挤进同一轮，此时数字必然相同，
**不可单独归因**；简报的「降级项」一节会自报这种情形）、以及**在该模型内部**
「换成主动公开」这条路会走向哪里。窗口表的**正下方**还有一张《每轮证据量》——
它回答「上面那些数字各自建立在几条行为上」：逐轮的 `n_actions`（动作）、
「其中发声」（排除 refresh / do_nothing 一类）、「进入引擎」（**这个才是分母**）、
引擎自己的声势权重 `volume`，以及该轮有没有维度**恰好贴到 `_clamp` 的边界**。

几条必须一起读的限制，简报正文里会自己声明，并有机器检查强制它在场：

- **反事实不是预测。** 分支假设「后续行为不变」，而现实里一旦真的公开，
  agent 的反应本身就会变——那正是模型答不了的部分。A 版（激励版）与
  B 版（机制版）**不是区间，是两个模型假设下的两个点**。
- **不做评分。** 不引用金标里那句作者手写的预期形状，也不把离线重放的
  偏离量当分数。金标自己声明它不是观测值。
- **不给建议。** 只说在该模型内部两条路径的高低，不说「应当采取 X」。
- **拐点一节并列报出模型侧与叙事侧，不一致就写「不一致」。** 实测里金标把
  拐点标在 P3，而「极化增速超过关注增速」这个可检信号在第 0 轮就已成立——
  简报把它写成**不一致**，而不是「拐点被复现了」。
- **后段无信息时要自报。** 两条判据**都不含自由参数**，因此不是「本文挑了个阈值」：
  ① 某一轮**零条行为**进入引擎 ⟹ 那一步激励项恒为 `tanh(0/8)=0`，状态是纯弛豫
  外推，**那一轮没有观测**；② 某个维度**恰好等于 0.0000 或 1.0000** ⟹ 等价于
  「夹之前已经越界」，是 `_clamp` 的边界产物而非读数。27 agent 那份样例两条都触发。

简报的**生成**是确定的（同输入同输出，`repro_check.py` 逐字校验）；
它**读取的那条曲线**不是（agent 每次说的话不同）。这两句话必须同屏出现，
否则「不可复现」会从一条有边界的性质变成不做确定性的借口。

## 设计取向

几条贯穿全项目的取舍，都不是随手决定的：

- **干净 clone 里一条命令能跑起来** 优先于技术上的先进。存储用 SQLite 单文件而非图数据库，
  LLM 客户端只用 `requests` 而非官方 SDK，`.env` 自己解析而非引入 `python-dotenv`——
  每少一个依赖，就少一个「装不上」的失败点。
- **不静默降级**。配置缺失、向量维度不匹配、FTS5 不可用，一律立刻报错并说清楚原因。
  这类项目最常见的失败不是算法错，而是跑到一半发现某个值是空的。
- **能离线验证的部分必须可真离线验证**。场景装载与存储层不依赖任何 LLM，
  因此可以进 CI、可以复跑、可以作为复现的起点。
- **不做没有收益的复杂度**。语料仅 33 个 chunk 的规模下，混合检索（RRF）不会带来
  可测量的召回提升，因此只保留词法与向量两条独立通路，不做融合。
  **并且要说清它现在没被用**：`store.py` 的 `search_lexical()` / `search_vector()`
  当前**零消费者** —— `scenario.py` 只往里写，仿真读的是金标阶段事件与知情映射，
  不查库。检索层是为「材料规模变大后按需取用」预留的，不是主流程的一环。
  把它说成「我们做了混合检索」会是假的；说成「两条通路都可用」也偏了，
  准确的说法是**通路建好、尚无调用方**。
- **产出物本身也要能离线复现**。原始推演曲线端到端复现不了（agent 每次说的话
  不同），但**给人看的那份东西**没有理由跟着一起不确定。决策简报不含 LLM、
  不含随机数、不含时间戳，因此同输入必然同输出，并被 `repro_check.py` 逐字校验。
  这条例外不是洁癖：不划这条边界，「不可复现」就会从一条有范围的结论，
  膨胀成所有地方都可以不确定的理由。
- **「不可复现」之外还有一半：这份产出到底是怎么跑出来的，它自己记不记得。**
  六维曲线之所以不确定，是因为它的输入是一次 LLM 抽样；正式口径因此是
  **多 seed 跑 N 次、报均值与方差**，而不是把一次抽样当结论。这一半现在的状态是
  **三支臂已经跑完并随仓库交付**，两件事分开说：
  - **已落地的是「可审计」**：产出的 `meta` 现在记 `seed` / `temperature` /
    `random_seeded`（老产出没这些键时，消费方一律显示「**未记录**」——
    缺键不是 `0`，本次确实没传也不是「未记录」，三态分开）；`stability.py`
    把随机性来源写成**唯一出处的一张表**（camel 端点采样 / 直调归类 / OASIS
    的 `refresh` 抽签 / `asyncio` 交错 / 重试抖动），手册里的同一张表由测试
    与代码逐行核对。`--seed` 这根杆也**真的拉上了**：它原先只到 LLM 端点，
    而 agent 每轮看到哪几条帖是 OASIS 用 `random.sample` 抽的（入库产出里
    `refresh` 324 次，是 774 个动作里最大的一项），这条路径用的是标准库全局
    RNG，所以进程里播一次种就覆盖到了。**它管不到的是 LLM 端点采样
    （服务端只「尽力」遵守）与 `asyncio.gather` 的交错顺序**——后者决定写库
    次序，也就决定 `post_id` 分给谁、后一个 agent 点赞的是哪条帖。所以
    `--seed` 买到的是「钉住」，不是「可复现」，这句话写在产出里、不写在文档里。
  - **跑完的是「一批」**。原先的次序是「先拍板再花钱」，因为有两个内核常数
    （每轮注入体量该不该减、`VOLUME_REF` 该不该随 agent 数走）**任一个改动都会让
    已经跑出来的臂全部作废**。这两个常数**现已拍板：保持现状，不改动** ——
    理由与那两个问题本身无关：**已入库、逐字可复核的产出优先于「更保真」**。
    约束解除后，批次在**当前基线**上跑完并随仓库交付：`data/runs/seeds/` 下
    三支 seed 臂（同一批设定、只换 seed，27 agent × 15 轮），连同批次清单
    `batch.json`、逐臂清单 `arm.json` 与离线汇总 `stability.md` / `stability.json`。
    **复核这一批不花钱、不联网**：`python backend/stability_report.py --root data/runs/seeds`
    会从这三支臂重算一遍汇总，读数应与入库那份一致。三支臂的**重放偏差**都在
    4.9e-05 量级，**驱动峰在臂之间不一致**（R5 落在 seed22、R6 落在 seed11 与
    seed33），10 条金标断言里**只有 AS-2 一条翻转**（另两条全程「不可判定」）——
    这些是**离散读数，不是分数**。
    跑批工具本身仍是原来那套：`run_seeds.py` 不给 `--yes` 就只打印墙钟与 token
    估算（并标明**那是外推不是测量、不含金额**）一个请求都不发，臂目录已存在不
    覆盖、三个输入文件逐臂拷贝并核对 sha256 同源、臂间协议不一致直接拒绝，
    单臂失败就停下并报出是第几支；`stability_report.py` 是纯离线汇总，逐轮逐维
    给跨臂均值与范围、逐臂重算金标三态并归并成「稳 / 翻转」，**混合批次拒绝出
    报告而不是偷偷求平均**。它产物开头写死一句「这不是分数，是同一批设定下
    N 次抽样的离散」，且贴过边界的维度（`trust` / `polarization` / `risk` /
    `stability`）只标不判——夹逼会把跨臂离散压小，那种离散是假的。
    **一处如实交代**：这三支臂清单里的两段 2 KB 中文日志尾巴**没有入库** ——
    采集成子进程输出时没对齐子进程编码，中文被换成了替换符且不可还原，故整条
    去掉并就地写了一句 `tails_dropped`；生成器**已修**（起子进程时带
    `PYTHONIOENCODING=utf-8`），此后重跑得到的尾巴是干净中文。去掉的只是给人看
    的日志，`returncode` / `out_sha256` / 口径键这些**机器判据一条没少**。
- **代价也写进文档，不只写收益，而且认错了要改**。六维回注会经 agent 记忆
  逐轮累积，实测每轮 prompt 比不回注高得越来越多（3 轮里从 +12% 拉到 +100%）。
  本项目曾据此把回注判为上下文增长的**主因**，并计划子类化 `AgentMemory` 去治它——
  **这个归因是错的，已更正**：`--no-feedback --no-knowledge` 那一行
  （1220 → 2113 → 4810）**关掉回注照样以 ~2×/轮的速度涨**，真正的驱动是
  OASIS 原生记忆累积（`SocialAgent` 未传 `message_window_size`，`retrieve()`
  全量返回，且评论表只增不删），回注只是次级放大器。**更正记录留在
  [`进度.md`](进度.md) 里。**

  当时还留了一句话：「`max_tokens=16384` 兼作上下文上限，增长会**饱和**而非爆炸；
  逼近上限后 camel 会静默丢弃旧记录，**这个要等 agent 数上去之后再测**」。
  **已经测了，两半各对一半**：3 agent × 15 轮确实远未触线（单次调用 886 → 7,695），
  但 27 agent × 15 轮**从第 6 轮起就开始截断，入库那次全程 767 次、
  单次最多丢 1,234,443 token**（换一次运行是 653 次 / 930,238 token）。
  「饱和」是对的，只是饱和的方式是**悄悄截肢 agent 的记忆**，而不是曲线变平——
  而这个项目最防的就是这种不报错的失效。现在它被接成了可机检的事件
  （`simulate.install_truncation_watch`），逐轮记进产出，简报里按 `truncated` /
  `truncation_unparsed` 两条降级项报出来（老产出没这个键时改报
  `no_context_record`，说的是「没记录」而不是「没截断」）。
- **「接线通了」不等于「语义对了」**。知情范围那个泄漏是审计没查出来的：
  它核了「谁产出、谁消费、谁接线」，四段全通，于是判为「有产出方」——
  而真实情况是注入每轮原样重复、把 P3/P4 的事实在第 0 轮就告诉了 agent。
  缺陷不在链路上，在语义上，只有**跑一次看输出**才能发现。
  这也是本项目的检查为什么尽量写成「断言某个东西**不在场**」：
  断言在场，永远抓不到这类问题。
- **校验环节自己也会出错，而且错得更难看。** `repro_check.py` 的第 3 层要跑两次
  完整推演来比曲线，而它构造命令时**没传 `--out`** —— `weiran.simulate` 的默认值是
  `data/simulation`，产出就写在那里面的 `twitter_rounds.json`。于是**跑一次自检，
  就把 27 agent × 15 轮的结果静默覆盖成 5 agent × 3 轮的临时结果**。不报错、
  不提示、退出码正常，跑自检的人以为自己在让仓库更可信。发现它的是
  `test_real_run_output_is_current` —— 那条守「落盘的简报必须与落盘的产出对得上」
  的哨兵，是全场唯一醒着的东西。代价是那份产出当时从未提交，**961 秒白花了一次**。
- **修上面这条时又栽了第二次，而这一次测试是全绿的。** 修法是「把 `--out` 指到
  一个临时目录」，于是 `sim_argv()` 传了 `$TMP/e2e_a.json` —— **一个文件名**。
  而 `--out` 的粒度是目录：推演从它**读**画像与知情映射、再往它里面**写**产出。
  结果是第 3 层在读 `twitter_profiles.csv` 那一步 `FileNotFoundError`，
  **整层跑不起来**。它没被发现，是因为第 9 套测试当时断言的是
  「argv 里有没有 `--out`、它等不等于入库产出」—— 两条都真，
  而发出去的命令根本跑不通。**只断言「参数在场」的检查，是恒真检查。**
  处置换了个性质：不看参数字符串，改成**把运行目录真的造出来**
  （`_seed_run_dir()`，可离线测试），能不能跑取决于磁盘上有没有那几份输入；
  并加一条**真的把 CLI 跑起来**的端到端验收（`python repro_check.py --agents 1
  --rounds 2`）。两次翻车的共同点写在 `repro_check.py` 的模块 docstring 里：
  第一次是产物被毁而没人看，第二次是**测试全绿而工具已经废了**。
- **金标规模跑出来是崩的，这件事写在最显眼的地方。** 到 2026-09-14 为止仓库里
  所有产出都是 **3 agent**，而金标写的是 **27 个角色**。跑一次 27 agent × 15 轮
  （入库那次 657 秒 / 774 条动作）之后，两个数字必须同屏出现：**轮 0 有 21 条行为
  进入六维引擎，轮 14 只剩 9 条**（45 条动作里只有 9 条是发声，其余是 refresh /
  do_nothing）；**信任、极化、风险、稳定四个维度从 R11 起贴到 `_clamp` 的边界
  锁死 4 轮**（风险更早，R9 就贴上了）。代价是具体的：简报的五个决策窗口里
  **四个的 Δ(A−实际) 落到 +0.0025 及以下，其中 P2、P4 恰好 +0.0000** ——
  五行业务对照是这份简报存在的理由，而它在金标规模下没有区分度。
  病因不是「上下文爆炸」。**注意这条结论的证据换过一次**：原先的依据是
  「3 agent 那次零截断却同样后段无信息」，而那条旧记录已被证伪（见下），
  所以那个推理**作废**；现在支撑它的是下面的 A/B —— **截断更少的那一臂反而是
  崩得更狠的那一臂**（`event_order` 截断 11/16/0、却贴壁 3/7/3 并塌了一次；
  `phases` 截断 41/35/35、一次没贴）。截断数与失效不对应，所以失忆不是主因。
- **「事件太稀」这个诊断也被实测推翻了。** 一开始的假设是① agent 只在有新事件时
  说话，而 P1–P5 落在轮 0/2/5/8/14、轮 9–13 是空档 —— **事件太稀**，
  于是把金标里 17 条 `event_order` 明细接成了第二条注入源（`--events-from`），
  在 3 agent × 15 轮上做 A/B、**每臂 3 次**。结果：

  | | 归类条数 | 贴壁轮数 | 五个窗口 Δ(A−实际) |
  |---|---|---|---|
  | `phases`（对照） | 28 / 30 / 28 | 0 / 0 / 0 | 各不相同（+0.0158 ~ +0.1749） |
  | `event_order` | 37 / 40 / 42 | 3 / 7 / 3 | 两次更大，**一次全部塌成 +0.0000** |

  **加密确实抬起了前段话语量（+38%，三次不重叠），但救不回后段**：R11–R12
  两臂一起落到地板（≈1 条）。而且它**在要害上更糟** —— 更密的事件把系统更早
  推进吸收壁区，最差那次贴壁 7 轮、**五个窗口的 Δ 全部塌成恰好 +0.0000**，
  正是 27 agent 那个失效形状提前到 3 agent 出现了。
  所以**真正的约束是②（引擎末步的硬夹 `_clamp(·, 0, 1)` 是吸收壁，没有随接近
  边界而增强的回拉力），不是①**。①救不了、不该单独上线，默认继续留在 `phases`；
  `event_order` 更适合当**消融对照**用（它正好能造出「事件更密」那一档）。
  引擎那条要动就得连 `validate.py` 的消融表一起重算，是模型语义问题——**本作品没有做
  这一改动**：成因已定案、三个杠杆逐个单独打开都移不动输出峰（见 `进度.md`）。
  这是一条**已声明的边界**，不是一个「即将修复」的承诺。
- **一条旧记录被自己的实测证伪了，记在这里。** 早先写着「3 agent 那次**全程零截断**，
  轮 9–12 甚至 0 条进入引擎」。这次同规模、同默认口径的对照臂得到的是
  **截断 35~41 次**、零行为轮 **0 / 0 / 2**（不集中在 9–12）。两次至少有一处不可信，
  而旧那条是 **n=1**。**在新结论落地前，旧那条不再当事实引用。**
  （差异来源**没有再去定位**：那条旧记录已被作废、不再被任何结论引用，
  追它不产出可引用的东西。）

  这三条合起来才是这一节要说的：**参数一改、规模一变，结论的形状会变；
  而 n=1 的记录撑不住。** 上面表格里每一格都是 3 次的实测，不是推理。
  在此之前，先把「这一轮的六维状态是拿几条行为算出来的」变成不可静默的量。
  还有一条不能省：**27 agent 那一跑跑了两遍，两遍都崩，数字不一样**（第一遍 R14
  只剩 3 条、截断 653 次、四个窗口塌成 0；入库的第二遍 R14 有 9 条、截断 767 次、
  三个窗口在 0.0025 以内）。**差异本身就是结论的一部分** —— 它说明这个规模下
  的窗口数字既没有区分度，也不稳定，所以上面的「崩」写的是两遍共有的形状，
  而不是某一次的具体数值。

## 上游与许可

本项目基于开源项目 [MiroFish](https://github.com/666ghj/MiroFish) 二次开发，依据
**AGPL-3.0** 发布。沿用其「OASIS 多智能体仿真 + 角色画像 → 推演驱动 → 知识存储」
的整体管线；其中**逐字复用**两处（可用动作列表、profile 格式定义），**重写**两处
（推演驱动、记忆存储），**新增**两处自研（六维世界状态引擎 + 闭环回注、只读展示层
`weiran/viewer.py`）。上游的 **Web 端前端与实时命令下发不复用** —— 本项目没有
「重写上游前端」这件事，界面是另起的一个只读页面，命令下发至今没有。
上游版本、修改范围与自研边界逐项见 [`NOTICE`](NOTICE) 与
[`docs/开源及第三方资源使用清单.md`](docs/开源及第三方资源使用清单.md)。

> 关系是两个层次，别把它们混成一句话：**本项目是衍生作品**（这一点不因「没整份搬文件」
> 而改变——AGPL-3.0 判定衍生关系不取决于是否逐字复制），而**逐字复用的只有两处**。
> 说「二次开发」是定性，说「复用两处」是定量，两者都要在场。

AGPL-3.0 第 13 条：本项目若以网络服务形式对外提供，须向使用者提供完整对应源码。
本项目公开发布于代码托管平台，满足该义务。展示层只绑 `127.0.0.1`、只接受 GET、
只读盘上产物，是本地查看工具而非对外服务；即便按最严的口径读这一条，源码公开
这一点也已经满足它。
